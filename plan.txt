✅ Project: Root Cause Analysis (RCA) Assistant
1. Business Problem (Real‑World Framing)
Context
Organizations often perform RCA after incidents (missed deadlines, outages, customer complaints, operational failures).
The problem is:

Analyses are inconsistent
Root causes are confused with symptoms
Mitigation actions are vague

Goal
Build a multi‑agent AI assistant that guides structured RCA using reasoning, validation, and review—similar to how real post‑incident reviews are done.

2. What the RCA Assistant Does
Input

Incident description (free text)
Optional context (team, timeline, constraints)

Output

Clear problem statement
Possible root causes (people / process / system)
Contributing factors
Corrective actions
Preventive actions

✅ No historical datasets
✅ No automation tools
✅ Reasoning‑first system

3. Multi‑Agent Architecture
UserProxyAgent
      ↓
Incident Analysis Agent
      ↓
Root Cause Identification Agent
      ↓
Mitigation & Prevention Agent
      ↓
Critic / Validator Agent
      ↓
Final RCA Report

This structure alone makes the project interview‑credible.

4. Agent Roles & Responsibilities
4.1 Incident Analysis Agent
Purpose
Understand the incident clearly and restate it correctly.
Tasks

Identify:

What happened
When
Who was impacted


Separate symptoms vs problem

Output

Refined problem statement
Key facts & assumptions


4.2 Root Cause Identification Agent
Purpose
Identify likely root causes logically.
Method

Uses basic RCA reasoning:

People
Process
Tools / Systems
External factors



Tasks

Generate 3–5 plausible root causes
Explain how each caused the issue
Distinguish root cause vs contributing factor


4.3 Mitigation & Prevention Agent
Purpose
Turn analysis into action.
Tasks

Corrective actions (fix now)
Preventive actions (avoid recurrence)
Prioritize actions by impact & effort


4.4 Critic / Validator Agent
Purpose
Quality control (this upgrades your project from “demo” to “system”).
Checks

Are causes actually root causes?
Are actions specific or vague?
Is logic consistent end‑to‑end?

Behavior

Approves OR requests revision once


5. End‑to‑End Workflow

User submits an incident description
Incident Analysis Agent clarifies the problem
Root Cause Agent proposes causes
Mitigation Agent suggests actions
Critic Agent validates the analysis
Final structured RCA report is returned

✅ Deterministic termination
✅ No infinite loops
✅ Clean separation of reasoning stages
